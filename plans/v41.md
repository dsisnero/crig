# v0.41.0 Porting Plan

**Upstream release:** `v0.41.0` (commit `68b4eabb8c9cf749ca73c917b9306e97fb0eda24`)
**Previous baseline:** `v0.40.0` (commit `a551c4c5c5df5d26b07111c722cc26ffb2777561`)
**Vendor:** `vendor/rig` now at `v0.41.0`
**Migration guide:** `vendor/rig/MIGRATING.md` covers 0.38→0.41 with before/after code and a symbol reference

## Summary

Major refactor: `rig-core` split into `rig-core` (provider-agnostic contracts) + `rig-agent` (agent runtime). 92 files changed in `rig-core` (−31,956 / +8,189), 31 new files in `rig-agent` (+39,250). Crystal port keeps unified module structure but must align behavior with both crates.

**Key findings from release discussion #2225:** Crate split, one tool path (`Tool::call(&mut ToolContext, Args)`), event-specific provider-independent hooks, `AgentRunner` as only execution path, `PortableTool` contract, WASM target-based (no feature flags), `dynamic_context` restored as hook, `#[rig_tool]` required-ness follows parameter types, embeddings shared transport, MIGRATING.md exists.

### 2.4 Tool system — PortableTool, ToolOutput, simplified dispatch

This is the largest refactor. Upstream collapsed multiple parallel APIs into one.

- [x] **`PortableTool`**: implement context-free tool contract in `src/crig/tool/portable.cr`. On the Crystal side, `Crig::Tool` remains the classic contextual trait; `PortableTool` blanket-implements it.
- [x] **`ToolOutput`**: implement content block types in `src/crig/tool/output.cr`. Strings stay literal text, `JSON::Any` stays JSON, multimodal tools use `ToolResultContent`.
- [x] **Single `call` method**: `Tool::call(&mut ToolContext, Args) -> Result(Output, Error)`. Remove `classify_error`, `call_with_extensions`, `call_structured`.
- [x] **`ToolDyn` → `DynamicTool`**: rename the public erased-tool type.
- [x] **`ToolSet` simplification**: `get_tool_definitions` and `documents` become synchronous and infallible. Registration no longer returns `Result`.
- [x] **Dispatch consolidation**: `ToolSet::execute` and `ToolServerHandle::execute` replace the three-way `call`/`call_with_extensions`/`call_structured` split.
- [x] **Error consolidation**: replace `ToolError`, `ToolFailure`, `ToolReturn`, `ToolOutcome`, `ToolExecutionResult` with `ToolExecutionError`, `ToolErrorKind`, `ToolResult`.
- [x] **`ToolContext`**: replaces both `ToolCallExtensions` and `ToolResultExtensions`. `.tool_extensions(...)` becomes `.tool_context(...)`.
- [x] **Registration names**: `dynamic_tools(sample, index, toolset)` → `retrieved_tools`; `ToolSetBuilder::dynamic_tool(ToolEmbedding)` → `retrieved_tool`.
- [x] Update `src/crig/tool/result.cr` to match upstream `tool/result.rs` changes.

### 2.5 HTTP client / SSE

- [x] Update SSE helpers — 227 vs 374 lines upstream (retry/resume logic, stream types): mid-stream transport errors now start a fresh retry cycle (`retry(&err, None)`), matching upstream `SourceState::Open` behavior; content-type/status validation, last-event-id forwarding, and invalid-utf8 recovery already aligned

## Phase 3 — Agent runtime alignment (rig-agent parity)

Crystal keeps agent code in `src/crig/agent/` (no crate split) but must match rig-agent v0.41.0 behavior.

### 3.1 Agent builder

- [x] Update `src/crig/agent.cr`:
  - `AgentBuilder::tools(Vec)` → repeated `.tool(...)` or `dynamic_tools(Vec(DynamicTool))` (deprecated with backward compat)
  - `dynamic_context` preserved (public API unchanged)
  - Provider-independent hooks: `AgentHook` methods no longer carry completion-model type parameter
- [ ] Response retry hooks (`on_retry`, #2182) — upstream PR after v0.41.0 baseline

### 3.2 Agent runner — only execution path

- [x] Remove `agent.completion(...)` / `agent.stream_completion(...)` — deprecated methods removed (matching upstream, which has neither); replaced with an internal `build_completion_request` used only by the deprecated `StreamingPromptRequest`. Also removed the Crystal-only `StreamingCompletion` trait (`Agent` keeps `StreamingPrompt`/`StreamingChat` only). Added missing `static_context` seeding to `AgentRunner` (agent static context documents now reach the runner path).
- [x] `AgentRun::new(prompt).with_history(history)` remains as sans-I/O state machine for custom drivers
- [x] Agent's model is fixed and private (no per-call `.model(...)` / `.model_opt(...)` setters)
- [x] `Extractor` routes through full hook lifecycle (was bypassing hooks)

### 3.3 Agent hooks — event-specific, provider-independent

- [x] Replace `on_event` + `StepEvent` + `Flow` with event-specific methods: `CompletionCallAction`, `ToolCallAction`, `ToolResultAction`, `InvalidToolCallAction`, `ObservationAction`
- [x] `CompletionResponseEvent` / `StreamResponseFinish` expose canonical Rig content — runner-based dispatch uses canonical types: added `StepEvent.text_delta`/`tool_call_delta` factories + `on_text_delta`/`on_tool_call_delta`/`on_stream_response_finish` observation hooks (backward-compatible defaults via `on_observation`); `on_text_delta` dispatched in the streaming path
- [x] `AgentHook` and `HookStack` have no completion-model type parameter
- [x] Invalid-tool hooks return `None` to defer; every explicit action (including `Fail`) is terminal
- [x] Post-batch streaming event: `ToolExecutionCommitted` — added to both `MultiTurnStreamItem` and `StreamToolExecutionCommitted` in low-level stream

### 3.4 Prompt request

- [x] Update `src/crig/agent/prompt_request.cr` and `prompt_request/streaming.cr` — added upstream per-request builder overrides (`preamble`, `temperature`, `max_tokens`, `tool_choice`, `additional_params`) and `without_*` clearing methods on `AgentRunner`, `PromptRequest`, and `TypedPromptRequest` (matching `forward_prompt_setters!`); verified via the recorded request on mock completion models
